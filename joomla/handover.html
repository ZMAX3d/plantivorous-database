Handover · Plantivorous database

Putting the carnivorous-plant database on plantivorous.co.za

A static catalogue that runs alongside Joomla. No PHP, MySQL or Joomla extension is required. This page is written for the website creator and the hosting provider.

Live demo GitHub repository Markdown version

Short version: upload index.html and assets/ into public_html/database/, then add a Joomla External URL menu item pointing to /database/. That is a working deployment. Everything below is optional polish or automation.

1. What is being deployed

The catalogue is a static single-page app: HTML, CSS, JavaScript and JPEG/SVG images. Joomla keeps running exactly as it does now. There is no server-side code to install and no database to create.

Upload these

index.html
assets/
├── css/
├── fonts/
├── img/
└── js/
    ├── app.js
    ├── data.js
    └── world-map.js

Do not upload

  • scripts/
  • node_modules/
  • data/ (maintainer source only)
  • .github/
  • .photo-test/

The ready-made plantivorous-database-static.zip contains only the runtime files.

Disk use is about 105 MB uncompressed (96 MB of photographs). The app uses hash links such as #/species/cephalotus-bananito, so it needs no URL rewriting and works from any subfolder.

2. Host requirements

  • Any normal web host — Apache, LiteSpeed or Nginx — with HTTPS.
  • Write access to a folder such as public_html/database/.
  • Standard MIME types for .html, .css, .js, .jpg, .svg and .woff2.
  • No PHP version requirement, no database, no cron job.
  • Optional, for automatic updates: an FTP, FTPS or SFTP account limited to the database folder.

3. First deployment (host / cPanel)

  1. Open cPanel → File Manager → public_html.
  2. Create a folder named database.
  3. Upload plantivorous-database-static.zip into it and choose Extract.
  4. Confirm the structure is public_html/database/index.html and public_html/database/assets/... — not a nested folder.
  5. If the host requires it, set folders to 755 and files to 644.

Then test:

  • https://www.plantivorous.co.za/database/
  • https://www.plantivorous.co.za/database/#/species/cephalotus-bananito

A. External URL menu item

  1. Menus → Main Menu → Add New Menu Item.
  2. Choose System Links → External URL.
  3. Link: /database/. Title: Plant Database.
  4. Optional: set Target Window → New Window.
  5. Save and open the menu item.

B. Wrapper menu item

  1. Create the menu item as above, but choose System Links → Wrapper.
  2. URL: https://www.plantivorous.co.za/database/?embed=1.
  3. Width: 100%. Height: 1200 (or whatever suits the template).
  4. Enable Scroll Bars if Joomla offers the option.

?embed=1 hides the app’s own header and footer, so there is no double header. It adds a slim dark bar with ← Plantivorous shop and “Carnivorous plant database”. The shop link opens in the parent window.

Iframes are weaker for SEO and can feel awkward on mobile. Use Option A for the main navigation; use the Wrapper for a secondary tab.

C. Custom HTML module

Paste the contents of joomla/custom-html-embed.html into a Custom HTML module assigned to a full-width position. If the editor strips the <iframe>, switch that module’s editor to No Editor or paste in the HTML source view.

The snippet is responsive: width:100%, height:calc(100vh - 160px), min-height:720px.

5. Automatic updates from GitHub (FTP / SFTP)

The repository contains .github/workflows/deploy-ftp.yml. It uploads only index.html and assets/ to the host. It runs on relevant pushes, manually from the Actions tab, and after the monthly ICPS check when new taxa were added.

Safe by default: if the secrets below are missing, the workflow skips the upload and reports a notice. It does not fail and does not break the site.

Repository secrets

Add them in GitHub: Settings → Secrets and variables → Actions → New repository secret.

Host-side setup

  1. Create a dedicated FTP/SFTP user whose start folder is public_html/database/.
  2. Enable FTPS (explicit TLS) or SFTP. Avoid plain FTP if the host supports encryption.
  3. Do not give the deploy user access to public_html root, configuration.php or the Joomla administrator folder.
  4. If the host has a firewall, allow FTP/SFTP from GitHub Actions. Runner IPs are dynamic, so use strong credentials and TLS rather than an IP allowlist.
  5. The target folder should contain only the catalogue. The workflow does not delete unrelated files, but a dedicated folder avoids surprises.

First automated deployment: upload the site once manually, add the six secrets, then run Actions → Deploy static site (FTP/SFTP) → Run workflow.

If the host requires key-based SFTP only, this password-based action will not work. Ask for an FTPS account, use manual uploads, or replace the action with an SFTP key action.

6. Caching

After a deployment the host, Cloudflare or LiteSpeed Cache may still serve old CSS/JS/images.

  • Purge the Joomla/CDN cache after each deploy.
  • Or hard-refresh: Ctrl+F5 (Windows) / Cmd+Shift+R (Mac).
  • Optionally give assets/js/data.js a short cache lifetime (it changes monthly) and images/fonts a longer one. Only do this if mod_headers is enabled.

8. Privacy and licensing

  • The collection and wishlist are stored in the visitor’s browser (localStorage) only. Nothing is sent to the host or Joomla.
  • The catalogue is read-only for visitors. Only maintainers change it through the repository and a new deployment.
  • Photographs are CC0 / CC BY / CC BY-SA / public domain, with visible attribution and licence links. Keep the credit panel and licence text intact.
  • Taxonomy and registration facts come from the ICPS Carnivorous Plant Names Resource.
  • The site has no server-side component, so Joomla outages cannot break the catalogue — and the catalogue cannot modify Joomla content or its database.

9. Handover checklist

  • public_html/database/index.html exists and loads.
  • public_html/database/assets/ contains css, fonts, img, js.
  • /database/?embed=1 hides the app header/footer and shows the back bar.
  • Joomla menu item added (External URL or Wrapper).
  • Optional: six FTP secrets added and the deploy workflow run successfully.
  • Cache purged; checked in a private window and on mobile.
  • Photo credits and licence text still visible.
